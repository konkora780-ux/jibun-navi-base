# じぶんNaviベース 開発前 調査報告（Webアプリ版）

調査日：2026年8月19日
方針：**Windows PC + iPhone + Claude Code で、費用¥0で開発する**

---

## 0. 開発方式の決定

**ネイティブアプリではなく、Webアプリ（ブラウザで動くアプリ）として作ります。**

理由：WindowsではiPhoneアプリを作れません。Xcode（iPhoneアプリの開発ソフト）がMac専用のためです。ここは技術的に迂回できません。

Webアプリなら条件がすべて満たせます。

| 条件 | Webアプリでの実現 |
|---|---|
| Windows PCで開発 | ○ Claude Code + テキストエディタだけ |
| iPhoneで実走テスト | ○ Safariで開く。ホーム画面に追加すれば全画面 |
| 最終的にAIBOXで動かす | ○ AIBOXはAndroid＝ブラウザが動く |
| 費用¥0 | ○ GitHub Pages無料、Mapbox無料枠内 |

さらに、こんちゃんが既に使い慣れている「GitHubに置いて GitHub Pages で公開」のやり方がそのまま使えます。

## ⚠ 1. 最重要リスク：日本の車線データ

**Mapbox公式（日本語ページ）の記載**：

- 地図の見た目はゼンリン製
- **ルート計算・車線データは OpenStreetMap（OSM）**
- ゼンリンのナビ用データは個別契約・別料金（法人向け）

このアプリの最重要機能である車線案内は、**OSMの `turn:lanes` タグ（各車線がどの方向に行けるかを書いた情報）が、その道路に入力されているか**にすべて依存します。

- 都市部の大きな交差点 → 期待できる
- 高速道路・国道 → ある程度期待できる
- 岩手県内の一般道 → 欠損が多い可能性が高い

**Phase 1 はこれを実測するための段階です。** 使えないと分かれば、早い段階で方針転換できます。

## 2. 使用する技術（すべて無料）

| 用途 | 使うもの | 費用 |
|---|---|---|
| 地図表示・3D | **Mapbox GL JS v3** | 無料枠内 |
| 経路・車線データ | **Mapbox Directions API** | 無料枠内 |
| 目的地検索 | Mapbox Geocoding API | 無料枠内 |
| 現在地・速度 | ブラウザの Geolocation API | 無料 |
| 音声案内 | ブラウザの SpeechSynthesis API | 無料 |
| 画面消灯防止 | Screen Wake Lock API | 無料 |
| 幾何計算 | Turf.js（CDN読み込み） | 無料 |
| 公開 | GitHub Pages | 無料 |

**すべてCDN（インターネット上の配布元）から読み込むので、npmもビルドも不要です。** HTMLとJavaScriptのファイルをGitHubに置くだけで動きます。

**3Dについて**：Mapbox GL JS v3 の Standard スタイルで、3D建物・3D地形・動的ライティング（昼夜で光が変わる）が使えます。昼モード／夜モードもこの機能で実現します。

## 3. Mapbox無料枠との関係

| サービス | 無料枠 | 今回の想定 |
|---|---|---|
| 地図の読み込み | 50,000回/月 | 1回のドライブ＝1回。月100回程度 |
| Directions API | 100,000回/月 | 1ドライブで数回。月100回程度 |
| Geocoding（検索） | 別枠あり | 月数十回 |

**余裕で無料枠内**です。ネイティブのNavigation SDK（MAU課金）を使わないので、むしろ課金リスクが下がります。

**注意点**
1. Mapboxには**支出上限（ハードキャップ）の仕組みがありません。** バグで大量リクエストを投げると請求が発生します。
2. **位置が更新されるたびに Directions API を呼ぶ実装は絶対にしないでください。** これが唯一の危険な落とし穴です。経路取得は「ナビ開始時」と「ルートを外れた時」だけ。
3. Mapboxの管理画面で**使用量アラート**を必ず設定してください。

**確認が必要な点**：無料枠の数値は変動します。実装前に mapbox.com/pricing で再確認してください。

## 4. アクセストークンの扱い（重要・無料で安全にする方法）

Webアプリはソースコードが誰でも見えるため、トークンを隠すことはできません。**代わりに「使われても困らないトークン」にします。**

1. Mapboxで**公開用トークン（`pk.` で始まるもの）**を作成
2. そのトークンに **URL制限（URL restrictions）** をかける
   - 許可URL：`https://<GitHubのユーザー名>.github.io/*`
3. これで、他人が勝手に自分のサイトで使うことはできません

この方法なら**GitHubリポジトリはPublic（公開）で問題なく、GitHub Pagesも無料で使えます。**

**やってはいけないこと**：`sk.` で始まる秘密トークンをWebアプリに書くこと。これは絶対に禁止です。

## 5. 車線データの取得方法

Directions API に `steps=true` でリクエストすると、次の構造でJSONが返ります。

```
routes[0] → legs[0] → steps[] → intersections[] → lanes[]
```

`lanes` の各要素：

| フィールド | 意味 |
|---|---|
| `indications` | この車線から行ける方向（例: ["left","straight"]） |
| `valid` | この車線で今回の曲がり方ができるか |
| `active` | Mapboxが推奨している車線か |
| `valid_indication` | 実行に使う方向 |

- 車線は**必ず左から右の順**（index 0 が一番左）
- **車線情報が無い交差点では `lanes` フィールドそのものが存在しません** → 「取得不可」の判定はこれで確実にできます

## 6. 曲がった先の車線データは取れるか

**取れます。しかも追加リクエストは不要です。**

- `steps[i]` = 今の道路
- `steps[i+1]` = **曲がった先の道路** → その `intersections[].lanes` が「曲がった先の車線」
- `steps[i+1].maneuver` = **次々の曲がり方**
- `steps[i+1].distance` = 曲がってから次の曲がり角までの距離

ルートを1回取得した時点で、先読みに必要なデータは全部手元にあります。

## 7. Webアプリで自作が必要になる部分（ネイティブとの差）

ネイティブの Navigation SDK が自動でやってくれることを、自前で書きます。**ここがこのプロジェクトの実装量の中心です。**

| 機能 | 実装方法 |
|---|---|
| 自車位置をルート上に吸着 | Turf.js の `nearestPointOnLine` で最近傍点を計算 |
| 次の曲がり角までの距離 | ルート上の進行距離から算出 |
| 現在どのstepにいるか | 進行距離とstepの累積距離を比較 |
| ルート逸脱の検知 | ルートから40m以上離れた状態が3秒続いたら逸脱 |
| 自動再ルート | 逸脱検知でDirections APIを再呼び出し（最短10秒間隔の制限を設ける） |
| 到着予定時刻 | 残り距離とAPIが返す所要時間から算出 |

**精度はネイティブに劣ります。** 特にトンネル内や高架下ではGPSが飛びます。ネイティブのように車速パルスや加速度センサーで補完しないためです。

## 8. iPhone Safari の実務的な注意点

実装時にハマる箇所を先に挙げます。

1. **音声が鳴らない問題**：iOS Safariは、ユーザーがタップした操作を起点にしないと音声を出せません。→ 「ナビ開始」ボタンを押した瞬間に一度無音の発話を実行して、音声機能を「解禁」しておく必要があります。
2. **画面が消える問題**：`navigator.wakeLock.request('screen')` で防ぎます。iOS 16.4以降で対応。**要確認：実機で必ず動作検証してください。** 動かない場合は「無音動画をループ再生する」という代替手段があります。
3. **位置情報の許可**：HTTPS必須。GitHub PagesはHTTPSなので問題ありません。
4. **ホーム画面に追加**：Safariの共有ボタンから追加すると、アドレスバーが消えて全画面になります。実走テストはこの状態で行います。
5. **バックグラウンドでは止まる**：ブラウザを閉じたり画面が消えるとJavaScriptが停止します。画面をつけっぱなしにする前提の設計です。

## 9. AIBOXへの移行方法

Webアプリなので、移行は非常に簡単です。

1. **Phase 3**：AIBOXのChromeでURLを開くだけで動作確認できる
2. **Phase 4**：必要なら WebView（Webページを表示するだけのAndroidアプリ）で包んでAPK化
   - Android Studio は **Windows で動き、無料**
   - 全画面固定・自動起動・音量制御などが可能になる

**AIBOXで想定される問題**

| 問題 | 対策 |
|---|---|
| GPS内蔵が無い機種がある | 購入前に必ず確認 |
| Chromeのバージョンが古い | Mapbox GL JS が動くか要確認 |
| 描画性能が低い | **3D ON/OFF切替を最初から実装しておく** |
| 通信 | SIMまたはテザリングが必要 |
| ACC連動で突然電源断 | 状態の保存・復帰処理 |

**確認が必要な点**：AIBOX購入前に「Androidバージョン」「GPS内蔵の有無」「RAM容量」を確認してください。

## 10. 開発フェーズ（改訂版）

| Phase | 内容 | 環境 |
|---|---|---|
| **1** | 車線データ検証アプリ | Windows開発 → iPhone Safariで実走 |
| **2** | Webカーナビ（実用版） | 同上 |
| **3** | AIBOXブラウザで動作確認・最適化 | AIBOX実機 |
| **4** | WebViewでAPK化＋ハイウェイモード | Windows + Android Studio |
| **5** | 高度化（料金・渋滞・オービス等） | — |

**Phase 1 → 2 の判定方法（改訂）**

参考基準として「取得率30%以上・HIGH率50%以上」は残しますが、**この数値だけで打ち切り判断はしません。**

最終判定は次の8項目を合わせて行います。

1. 全体取得率　2. **道路種別別の取得率**　3. HIGH率
4. **Mapbox推奨との一致・不一致の傾向**　5. **GPS精度による影響**
6. 高速道路での実用性　7. 市街地での実用性　8. 地方一般道での実用性

| パターン | 状況 | 次の方針 |
|---|---|---|
| **A** | 全道路種別で十分に取得できる | SmartLaneを全面採用してPhase 2へ |
| **B** | 高速・国道・主要道路は十分、地方道は不足 | **対象道路を限定してSmartLaneを有効化**してPhase 2へ |
| **C** | ほぼ取得できない | SmartLane方式そのものを再検討 |

**地方一般道の取得率が低くても、高速・国道で使えるなら価値があります**（パターンB）。そのため `roadClass` ごとにSmartLaneの有効／無効を切り替えられる設計にしておきます。

# VOICEVOXナビ音声機能 仕様メモ（Phase 2以降）

**現時点では実装しない。** Phase 1の実走テストが終わり、方向性が固まってから着手する。

## 実装前に必ず確認すること（最重要）

このプロジェクトは `CLAUDE.md` に明記の通り、**意図的にWebアプリとして開発している**（Windows PCで開発するため。ネイティブアプリではない）。

しかし本仕様が前提とする構成（`iOS AVSpeechSynthesizer` / `Android TextToSpeech` / `VOICEVOX CORE` の iOS XCFramework 組み込み等）は**ネイティブアプリを前提**にしたもので、現在のWebアプリの構成とは前提が異なる。

着手前に、以下のどちらのアプローチを取るか調査・判断する必要がある：

1. **VOICEVOX CORE の WebAssembly(WASM) 版をブラウザ上で動かす** → Webアプリのまま実現できる可能性
2. **ネイティブアプリ化する** → 「Webアプリで統一する」という現在の方針そのものを転換する大きな決定になる

以下の原仕様の24番（最初に調査して報告）は、着手時点で必ず実行すること。古いブログ記事等ではなく、その時点のVOICEVOX公式GitHub・公式ドキュメントを確認すること。

## 以下、こんちゃんが提示した原仕様（2026-08-19）

### 1. 目標

通常のカーナビ音声だけではなく、独自の車線案内も自然な音声で案内する。

例：
- 「300メートル先、右折です」
- 「右折後は、一番左の車線がおすすめです」
- 「この先、右から2番目の車線がおすすめです」
- 「左側2車線を走行すると、その先の分岐がスムーズです」
- 「この先ジャンクションです。左側車線がおすすめです」
- 「2キロ先の出口に備えて、左側車線をおすすめします」

### 2. 音声システムを独立させる

ナビ本体とVOICEVOXを直接強く結合しない。以下のような抽象化を行う。

```
NavigationVoiceEngine

├─ NativeVoiceEngine
│   ├─ iOS AVSpeechSynthesizer
│   └─ Android TextToSpeech
│
└─ VoicevoxVoiceEngine
```

ナビ側は `speak("300メートル先、右折です")` のように呼び出すだけにして、実際にどの音声エンジンで読み上げるかはVoiceEngine側で切り替える。これにより、iPhone標準音声／Android標準音声／VOICEVOX／将来別の音声エンジンを変更できるようにする。

### 3. 最初のiPhone版

iPhone版では、まず確実に動作するApple標準TTSを実装する。同時にVOICEVOXを後から差し込める構造にする。

VOICEVOX COREをiOSへ組み込めるかについては、実装開始時点のVOICEVOX公式GitHub・公式ドキュメントを確認する。古いブログ等だけを根拠に実装しない。現在利用可能な、VOICEVOX CORE／iOS XCFramework／ONNX Runtime／VVM音声モデルの対応状況を確認する。

### 4. VOICEVOX COREによる端末内音声合成

可能で安定している場合は、インターネット接続不要でiPhone/Android端末内でVOICEVOX音声を生成する構成を優先して検討する。理由はカーナビなので、通信圏外／山間部／トンネル／高速道路／通信遅延でもナビ音声を止めたくないため。

ただし、VOICEVOX COREのモバイル組み込みが不安定・処理負荷過大・ライセンス上不適切などの場合は無理に採用しない。

### 5. フォールバック

VOICEVOXで音声生成できない場合でも、ナビ案内自体を止めない。優先順位：

```
VOICEVOX
    ↓ 失敗
OS標準TTS
    ↓
画面表示のみ
```

VOICEVOXのエラーでナビゲーション自体がクラッシュすることは絶対に避ける。

### 6. リアルタイム生成

ナビ中に可変文章をVOICEVOXで動的に生成できることを目標にする（固定録音音声を大量に組み合わせるだけにしない）。

### 7. 音声生成キャッシュ

同じ文章を毎回VOICEVOXで再生成しないよう、音声キャッシュを実装する。

```
VoiceCache
"300メートル先、右折です" → audio_xxxxx.wav
```

同じ文章が再び必要になったらキャッシュを再生する。ストレージ容量が増えすぎないよう、最大キャッシュ容量／古いデータの削除／LRU等も検討する。

### 8. 先読み生成

音声案内が必要になってから生成を始めると間に合わない可能性があるため、Mapboxから次のmaneuverが分かった時点で、必要になる可能性の高いナビ音声を事前生成する。ただしナビのGPS処理や地図描画を邪魔しないようにする。

### 9. SmartLaneRecommendationとの連携

独自車線案内とVOICEVOXを連携する。SmartLaneRecommendationの出力（RecommendedLane/Confidence/Reason）を、VoiceGuidanceManagerが自然な日本語へ変換する。

### 10. Confidenceに応じた音声案内

- **HIGH**：具体的に案内（例：「右折後は、右から2番目の車線がおすすめです」）
- **MEDIUM**：少し曖昧に（例：「右折後は、右側の車線がおすすめです」）
- **LOW**：独自音声案内をしない。Mapbox標準案内のみ
- **UNKNOWN**：独自車線音声なし。推測で車線を読み上げない

### 11. 案内文章生成

専用クラス `NavigationSpeechComposer` を作る。

入力：maneuver / distance / roadName / recommendedLane / laneRange / confidence / nextManeuver
出力：「300メートル先を右折です。右折後は左側車線がおすすめです。」

VOICEVOXへナビロジックそのものを持たせない。

### 12. 音声がうるさくならないようにする

独自車線案内を追加すると音声量が多くなる可能性があるため、できるだけまとめる。

悪い例：「300メートル先を右折です。右折します。右折後は4車線です。左車線がおすすめです。500メートル先を左折です。」
良い例：「300メートル先を右折です。右折後は左側車線がおすすめです。」

運転中に必要な情報だけを簡潔に伝える。

### 13. ナビ音声優先制御

音声案内が重ならないようにする。優先順位：

1. 緊急性の高い直近maneuver
2. JCT・高速出口
3. 車線案内
4. 次の次の案内
5. その他情報

車線説明を読み上げている途中でも、直前の右折案内が必要になった場合は右折案内を優先する。

### 14. 音声設定

設定画面に「ナビ音声：VOICEVOX／iPhone標準／Android標準／音声OFF」を用意できる構造にする。VOICEVOXを使用する場合は、利用可能な音声を選択できるようにする。

### 15. 話速

車載ナビに適した読み上げ速度（ゆっくり／標準／少し速い）を設定できるようにする。ただしVOICEVOXの値（speedScale等）を直接ユーザーへ表示する必要はない。内部的に変換する。

### 16. イントネーション

ナビとして聞き取りやすいイントネーションを優先する。「右から2番目」「左から2番目」「一番左」「一番右」「300メートル」「ジャンクション」「インターチェンジ」などが聞き取りやすいか実走テストする。必要なら辞書・読み・アクセント等の調整方法を検討する。

### 17. 音量

ナビ音声用の音量設定を用意する。将来的にAIBOXでは、車載オーディオとの共存も考慮する。音楽再生中に案内する場合のAudio Focus / DuckingについてもAndroid版で検討する。

### 18. オフライン対応

最終AIBOX版では、可能な限りVOICEVOXをオフラインで利用できる構成を目標とする。ただしモデル容量・メモリ使用量・CPU負荷を実機で測定する。

### 19. パフォーマンス計測

iPhoneとAIBOXの両方で、短文/長文生成時間・CPU負荷・メモリ・音声モデル容量・初回ロード時間・キャッシュ再生時間を計測する。ナビ用途なので、文章生成の品質より、必要なタイミングで確実に音声が出ることを優先する。

### 20. 音声生成が遅い場合

VOICEVOXのリアルタイム生成がナビに間に合わない場合は、先読み生成／キャッシュ／定型文の事前生成／OS標準TTSへの一時切替を組み合わせる。

### 21. iPhone→AIBOX

iPhone版でVOICEVOX COREによるリアルタイム音声が安定した場合は、Android/AIBOX版にも同じ考え方を移植する。ただし `NavigationSpeechComposer` / `SmartLaneRecommendation` / `VoiceCache` / `VoiceGuidanceManager` などのロジックは可能な限り共通化し、VOICEVOXとの接続部分だけを `VoicevoxIOSAdapter` / `VoicevoxAndroidAdapter` のように分離する。

### 22. ライセンス・クレジット

VOICEVOXは利用規約を必ず確認する。VOICEVOX本体だけでなく、使用する音声ライブラリ・キャラクターごとの利用規約も確認する。アプリ内の「設定 → このアプリについて」等に、必要なクレジットを表示できるようにする。正確な表記方法については、採用する音声の最新公式利用規約を確認して決定する。規約を推測で判断しない。

### 23. VOICEVOX Nemoも候補にする

キャラクター性を強く出したくない場合はVOICEVOX Nemoも候補として調査する。カーナビなので、聞き取りやすい／長時間聞いても疲れにくい／車内騒音下でも分かりやすい声を優先する。実際に数種類を試聴・実走テストした上で決める。

### 24. 最初に調査して報告

この追加仕様に着手する際は、すぐ大量の実装を始めず、まず以下を調査する：

1. 現在のVOICEVOX CORE安定版
2. iOS対応状況
3. Android対応状況
4. iPhone実機に組み込む正式・現実的な方法（Webアプリのままか、ネイティブ化が必要か含む）
5. Android/AIBOXへ組み込む方法
6. 必要なVVM/ONNX Runtime
7. モデル容量
8. ライセンス
9. クレジット表記
10. リアルタイムナビ用途で十分な生成速度が出る可能性
11. オフライン利用可能性
12. Mapbox Navigation SDK（またはこのアプリのMapbox GL JS構成）との同時利用で想定される負荷

必ずVOICEVOX公式情報を優先して確認する。

### 25. Phase 1でのVOICEVOX目標（着手時点での最低ライン）

最初のiPhone実走テストでは、最低限、次の3種類を動的または事前生成音声で再生できることを確認する：

- 「300メートル先、右折です」
- 「右折後は、一番左の車線がおすすめです」
- 「この先、右から2番目の車線がおすすめです」

同時に、音声生成時間／GPSへの影響／Mapbox地図描画への影響／音声が遅れないかを記録する。

## 最終目標

最終的にはAIBOXで、「300メートル先、右折です。右折後は、一番左の車線がおすすめです。」のように、Mapboxのナビ情報とSmartLaneRecommendationによる独自車線判定を、VOICEVOXの自然な音声で案内するカーナビにする。

**ただし、VOICEVOXが失敗してもカーナビそのものは必ず動き続けることを最重要条件とする。**
